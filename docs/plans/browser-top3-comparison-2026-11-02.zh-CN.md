# 三个头部浏览器插件的复核与吸收计划

调研日期：2026-11-02。结论：优先补全安装、可见执行、人工指认、交接和收尾这一条用户路径。虚拟鼠标是必要体验，但不是独有能力。不能从下载量直接推导用户数、留存或执行质量。

## 横向对比

| 维度 | BrowserSkill | dsh-browser-cdp | wqty123/dsh-browser | 我们 |
|---|---|---|---|---|
| 核心路径 | CLI/daemon + 扩展，Chrome/Edge Agent Window，借用已有页 | CDP 端点 / 本机 CLI / 内置兼容运行时，多种连接目标 | 桌面侧栏 / 自托管窗口 / 显式配置本机 Chrome、Edge | Native Messaging Broker + 已有 Chrome 扩展 |
| 安装 | 需 CLI 与扩展；已有 Chrome/Edge 商店入口 | 随包运行时与自动环境探测；连接和回退仍有配置复杂度 | 默认载体力求装完即用；Electron 安装与可选 Desktop bridge 有额外边界 | 已有 DSH 设置安装入口；首次仍需加载隐藏目录中的扩展 |
| 可见执行 | 侧栏/浮层，动作、耗时、截图，按对话展示 | 实时观察，直接点击、滚动、输入，点选引用进聊天 | 人机同页、侧栏/窗口；有虚拟鼠标实现 | 实际 Chrome 内指针；聊天内暂无持续执行视图 |
| 人工协作 | sync/context/expect，人工编辑后重新核对 | 直接操作观察窗、精确点选引用 | 用户可接手同一页面，任务隔离 | Stop/handoff、对话切换撤销；缺“我已改完，继续”的完整流程 |
| 工具与引导 | 六个分组工具、多种动作，skill 按需加载 | 结构化工具族、连接探测、错误分类 | 当前 35 个工具，含 scrape/select 等 | 13 个工具，含多种 act 动作；说明较长，缺 hover/select/结构化提取等能力 |
| 任务生命周期 | 所有权注册与清理状态；借用/归还明确 | 空间、连接、观察与控制管理 | 按任务隔离，窗口与页面载体可选 | 有租约与 release；任务完成未自动清理临时页 |

工具入口数量与可执行动作数量不是同一指标，6、13、34/35 不能直接排序。表内也不能推导竞品都已实现 Codex 的按轮次临时页自动清理。

## 最值得吸收的能力

### BrowserSkill：学习“协作协议与按需指导”

- 参考其 `skill` 短入口和按需参考资料，把我们长篇参数说明中的恢复流程拆出去。保留明确的默认浏览入口，避免必须记斜杠命令才可使用。
- 学习 `contextId`、目标条件 `expect` 和人工修改后重新同步的思路：只读操作可以复用适当的观察上下文，执行前核对决策所依赖的事实；不因无关时钟变化把整页判失效，也不把旧截图当作当前状态。
- 我们已经有 document epoch、ref 和动作后置条件。应在这些机制上增加“人修改后的核对与继续”，而非平行发明第二套权限模型。
- 借鉴任务页与借用页的所有权登记，清理只作用于自己的临时资源。
- 其扩展已经有商店入口，这是我们实际安装体验的差距。商店付款暂时受阻期间，优先把现有向导做完整，不承诺零点击安装。

证据：[插件说明](https://github.com/Tencent/BrowserSkill/blob/main/packages/dsh-plugin-browserskill/README.md)、[协作语义](https://github.com/Tencent/BrowserSkill/blob/main/packages/dsh-plugin-browserskill/skill/references/cooperation.md)、[会话所有权实现](https://github.com/Tencent/BrowserSkill/blob/main/packages/dsh-plugin-browserskill/src/sessions.ts)、[按需工具](https://github.com/Tencent/BrowserSkill/blob/main/packages/dsh-plugin-browserskill/src/lazy-tools.ts)。

### dsh-browser-cdp：学习“看得见、指得准、报错能处理”

- 最大可吸收项是用户在页面点选元素，再把结构化目标带入对话。减少“这个按钮”“右边第二项”的歧义，直接服务准确程度。
- 我们的引用必须绑定对话、tab、document epoch 和当前 ref；只传位置或裸 backendNodeId 不能跨页面沿用。切换、导航、元素替换后要求重新指认。
- 学习其点选失败五类：连接、目标、启用、命中、描述；把我们的错误映射成“发生了什么、是否已执行、下一步是什么”。
- 增加轻量执行卡：当前页面、动作、耗时、等待原因、Stop/继续入口。读取页面也应显示“正在读取”，不必假装移动鼠标。
- 实时画面按可见性启停、限制帧率；观察画面与模型截图分开处理，避免每帧进入模型上下文。

我们不应直接照搬 cookie 导入、多远端端点、默认宽泛执行脚本或容器启动策略。当前主线是用户现有 Chrome，不需要同时承担全部后端复杂度。

证据：[产品与连接说明](https://github.com/drscrewdriver/dsh-browser-cdp)、[点选结果与错误契约](https://github.com/drscrewdriver/dsh-browser-cdp/blob/main/src/worker/pick-contract.ts)。

### wqty123：学习“默认可用与有意义的动作反馈”

- 当前源码存在 `src/browser-electron/virtual-cursor.ts`：页面内指针、点击波纹、动作文字和同位置绘制抑制。必须撤回“虚拟鼠标只有我们有”的暗示。
- 借鉴其“文字告诉用户正在做什么”和减少重复绘制的方式。我们的点击/输入/按键/滚轮/等待反馈应一致，并验证严格 CSP、缩放、滚动、导航后的行为；不能只看静态截图是否有箭头。
- 默认选出能工作的载体，缺依赖时清晰回退，是值得学习的产品原则。我们应把原则用于“Chrome 已连接/待加载/后台模式不符/需要重载”，无需为此改造成 Electron 浏览器。
- 补齐下拉选择、hover、返回前进、结构化提取，比堆更多相似点击工具更能拓展日常任务覆盖。
- 同时看到其代价：Electron 下载与脚本许可、可选 bridge 安装、Desktop 更新后 bridge 失效等。它的“装完即用”也有条件，不能当作所有平台零配置的实测结论。

证据：[当前 README](https://github.com/wqty123/dsh-browser)、[虚拟鼠标实现](https://github.com/wqty123/dsh-browser/blob/master/src/browser-electron/virtual-cursor.ts)、[载体架构](https://github.com/wqty123/dsh-browser/blob/master/docs/architecture.md)。

## 我们应保留的定位，以及需要停止的宣传

可确认的组合：直接使用现有 Chrome 登录态；本地 Native Messaging，标准路径无需用户开启调试端口；动作 journal 防止不明结果盲目重放；ref/epoch/几何与视觉点击新鲜度检查；页面内反馈与明确交接。我们也使用 CDP，不能宣传为“完全不用 CDP”。不增加第二套浏览器运行时仍需本地 Broker 与扩展，不能称为没有本机组件。

这些机制是产品基础，不是已证明优于三个竞品的证据。BrowserSkill 同样有所有权、观察上下文和条件检查。不能再写“竞品没有安全校验”“虚拟鼠标独有”“下载少说明市场空白”。市场扫描红线也不等于漏洞判定；我们自己的市场卡仍有 HTTP 匹配告警，需要解释真实使用边界并复核扫描规则，不能拿单项标签比较安全等级。

建议定位：**让 DSH 在你已登录的 Chrome 里清楚、准确地操作；过程看得见，随时能接手，完成后收拾干净。** 最后一项目前是计划，发布宣传应待实现验收后再写为能力。

## 实施顺序与验收

### 第一步：交付 0.1.2（结束复核已发布）

范围锁定在个人模式、设置提示、输入按键指针、前台交接修复。结束时已核验发布提交 b64398e、远端标签、CI 和 Publish npm 流水线成功，npm latest=0.1.2；本轮竞品调研没有执行额外推送或发布，也没有重复进行发布后的全新安装验收。竞品调研不应把这次修复版扩成大版本。

### 第二步：临时页清理 + 执行状态

1. 增加任务级 tab 登记：创建者、任务、临时/交付/待接手用途、当前文档身份。
2. 真正任务完成时关闭自己创建且未保留的临时页；交付页、待登录/确认页和用户原有页保留。对话切换不等于任务完成。支持停止任务后的可见清理入口；浏览器重启、ID 复用或归属不明时不自动关闭。
3. DSH 卡片显示连接、等待、读取、输入、完成、已交接及失败原因；点击可定位到任务页。
4. 验收：多次搜索结束无临时页堆积；交付/待接手页仍在；切换对话不关错页；后台任务不能重新抢控；断线重连不重放未知动作。

### 第三步：页面指认 + 人工接手继续

1. 用户点选后形成带文档身份的目标引用，进入 DSH 输入草稿；不自动发送消息。
2. 操作暂停、用户修改、点击继续、核对修改、重新观察后继续。人工活动不是新指令来源。
3. 验收：同名按钮、DOM 替换、页面滚动和导航后，都能给出正确目标或明确过期；不把坐标静默投到新页面。

### 第四步：高频能力 + 指令成本

先补 select、hover、back/forward、表格/列表提取。缩短常驻工具说明、按需加载恢复资料，并测试工具发现率；不能为了省 token 导致模型忘记浏览器入口。Edge 沿已有 provider 接口补独立端到端验收；没有通过前保留实验标识。

商店上架与 60 秒真实演示可并行准备：演示“从市场安装 → 设置检查 → 输入搜索 → 切换接管 → 完成收尾”，用真实录屏与测试环境标注，避免只放架构词汇。源码吸收需核对具体文件许可证、保留适用声明，优先借鉴契约与交互而非照搬实现。

## 用任务评测决定是否更丝滑

固定同一机器、Chrome/DSH 版本、模型和提示词、网络条件与同一任务集，再做 3～5 次重复。安装路径用全新测试环境分别测，不把已有登录态优势混为算法速度。

| 指标 | 应记录的内容 |
|---|---|
| 首次可用 | 从插件安装到首个正确页面读取的时间、用户点击与失败点 |
| 任务覆盖 | 搜索比较、动态表单、下拉、hover 菜单、上传下载、人工登录、任务清理 |
| 准确度 | 已验证完成率、错目标次数、重复副作用、无法确认的结果 |
| 流畅度 | 首个可见反馈与动作端到端 P50/P95、无解释等待时长 |
| 接管 | Stop 后仍发生动作次数、人工编辑后继续成功率、旧对话重抢次数 |
| 成本 | 每任务工具调用与 token、按需指导后工具发现率 |
| 收尾 | 遗留临时页数、应保留页面误关闭次数 |

内部目标可先定：固定基准任务成功率 ≥95%；Stop 后新动作与误关用户页为 0；无标记临时页遗留为 0。时延目标需要基线后制定，不把网络加载或模型推理与插件耗时混在一起。达到目标也不等于已超过 Codex；Codex 同任务同环境结果未测时仅报告本项目成绩。

获客指标先用主动反馈或本地验收，不默认上传用户浏览内容或启用遥测。下载量之外，应关注安装成功、首任务成功和自愿反馈的继续使用意愿。
