# 产品核心、竞争力与实施规划

日期：2026-11-02。基线：已发布 0.1.2，正式支持 macOS + Chrome。依据[三项目竞品复核](browser-top3-comparison-2026-11-02.zh-CN.md)与本项目实现；竞品尚未做同机运行评测。

## 一、产品核心

**把 DSH 变成用户日常浏览器里可靠的操作伙伴：用户用自然语言下达任务，助手在已登录的 Chrome 中执行，过程看得懂，随时能接手，结束后能交付并收尾。**

用户购买的价值是“少操作、少猜测、少返工”。虚拟鼠标、Native Messaging、语义树和租约分别服务于反馈、连接、理解和控制边界；它们是实现手段。

第一阶段聚焦已经使用 DSH、希望继续使用现有 Chrome 登录态的 macOS 用户。核心场景：检索比较资料、填写业务表单、处理网页后台、下载所需文件，以及人工登录后继续工作。付款、验证码和重大业务决定需要清晰的人工交接。

## 二、体验承诺与竞争力

体验主张：**在熟悉的浏览器中，用一句话开始，看懂每一步，随时接手，顺利交付。**

| 支柱 | 用户获得的价值 | 当前基础 | 需要补齐 |
|---|---|---|---|
| 现有浏览器 | 继续使用自己的 Chrome 和登录状态 | 扩展 + 本地 Broker；标准连接无需手动开启调试端口 | 商店分发、清晰的升级与诊断 |
| 可见过程 | 知道助手当前做什么、停在哪里 | 页面内点击、滚轮、输入和按键反馈 | 聊天内执行卡、读取/等待原因、定位任务页 |
| 准确执行 | 降低点错、重复提交与假成功 | ref/epoch、几何与命中校验、后置条件、动作 journal | 人工点选、业务事实核对、复杂页面覆盖 |
| 可接手 | 临时改动或登录后还能继续 | Stop、handoff、前台对话控制边界 | 接手—修改—重新观察—继续的完整流程 |
| 有收尾 | 有结果，浏览器不越用越乱 | 建页分组、仅关闭助手创建的页面 | 临时页、交付页、待接手页的登记与清理 |

现阶段的竞争力是上述技术与交互基础的组合，尚未形成难以复制的壁垒。虚拟鼠标不是独有功能；使用已有登录态、所有权和准确性检查也有竞品实现。不能仅以工具数或测试数宣称领先。

最有机会建立的优势是 **DSH 日常任务的连续体验**：安装能完成、执行能看懂、人工能参与、异常能恢复、任务有收尾。长期可积累的资产包括真实故障对应的回归用例、带证据的兼容性矩阵、同条件任务评测、稳定的动作与生命周期契约，以及可靠更新带来的用户信任。宣传需有可复现证据。

## 三、对标 Codex 的目标

### 命名与品牌

保留 `dsh-native-browser`：`dsh` 说明生态，`native` 表达沿用现有本机浏览器的体验方向，`browser` 明确用途，也为以后接入 Edge 留出空间。这个名字帮助辨识和记忆，但不能保证搜索排名、流量或形成技术壁垒。

面向用户可使用显示名 **DSH Native Browser**，配一句解释：**让 DSH 在你已登录的浏览器里办事。** 文档说明它是社区项目；native 不表示 DSH 官方出品、不表示不用 CDP，也不证明原生性能领先。现阶段正式支持范围仍为 macOS + Chrome。

“Codex 级丝滑”拆成可验证的用户路径：

1. 安装后能直接用对话开始，不需要知道 Profile、lease、CDP 等术语。
2. 助手选对浏览器和页面，展示当前动作；等待有原因，失败有恢复入口。
3. 用户打断或切换时控制立即停止，助手不偷偷抢回。
4. 用户接手后可继续，重新核对当前页面，避免覆盖人工修改。
5. 任务完成后保留交付和待接手页，关闭自己的临时页，给出结果与来源。

“Codex 用户无缝切换”的目标是沿用熟悉的操作习惯：自然语言、可见动作、随时接手、结果交付和自动收尾。它不表示导入 Codex 私有会话、控制令牌、授权或配置。

“超越 Codex”作为远期目标，选择可测的具体维度：首次使用所需操作更少、DSH 内元素指认更直接、同条件任务完成更快或成功率更高、恢复与收尾更可靠。未取得同任务基线前不宣传整体超越。

## 四、分阶段实施

以下是建议版本归属，非已承诺的发布时间。每阶段通过验收再发布；实施发现规模较大时可拆版。

### 阶段 A：0.1.2 用户验收与可用性基线

0.1.2 已发布，先验收新安装、升级、个人模式、输入指针、对话切换和 Stop。记录安装失败的确切步骤，优先修阻断使用的问题。

产物：中文首次使用向导、已知问题清单、真实完整演示，以及至少 5 名自愿用户的结构化反馈。人数是募集目标，不是已有用户研究。默认不采集浏览内容或开启遥测。

### 阶段 B：0.1.3 候选——收尾与执行状态

**优先解决当前用户已经遇到的“看不到在干什么”和“结束后页面堆积”。**

- 建立任务与标签页所有权登记，明确 temporary、deliverable、handoff。
- 增加明确的完成收尾操作与会话结束兜底，区分任务完成、普通轮次结束、切换对话、中断与异常退出。长任务不能在每次 turn/end 都丢失工作页。
- 完成时仅关闭本任务创建且未保留的临时页。交付、待登录或待确认页保留；用户原有页释放控制并保留。
- 首版执行卡显示任务、页面、动作、耗时、等待原因、结果与 Stop，并能定位实际 Chrome 页面。读取时显示读取状态，无需虚构点击。
- 错误提供是否已执行、是否能重试及恢复步骤；对未知结果禁止盲目重放。

验收：正常结束无未标记临时页遗留；用户页、交付页和待接手页误关为 0；切换对话只交接不误清理；浏览器重启或页面身份不明时不按数字 ID 关页；Stop 后无新动作。

### 阶段 C：0.2.0 候选——精确指认与人工协作

- 用户点选页面元素，生成绑定对话、标签页、文档与目标身份的引用，进入聊天草稿，由用户决定发送。
- 完成“暂停 → 人工修改 → 继续 → 重新观察并核对 → 执行”的路径。引用过期时明确要求重新指认。
- 展示结果、交付页与继续操作入口。已有页面中的文字只作数据，不成为新的操作授权。
- 观察视图可见时按需更新，设置帧率与资源上限；人工观察画面不默认逐帧进入模型上下文。

验收：同名按钮能指准；导航和替换后旧引用不作用于新目标；人工填写内容不被静默覆盖；无需重开整段任务即可继续。

### 阶段 D：扩展日常任务覆盖与执行效率

按反馈优先补 select、hover、back/forward、表格与列表提取，完善已有上传、下载与对话框流程。工具入口保持清晰，避免为相似动作不断增加名称。

精简常驻说明，将较长的恢复和特殊页面资料按需加载。以工具发现率、任务成功率、工具调用数和 token 实测决定取舍。

验收：动态表单、下拉、hover 菜单、下载、受控上传、长页提取与人工登录后继续均有可重复任务；表格输出说明完整性与来源，不能把局部读取当全量。

### 阶段 E：扩浏览器与扩大分发

Chrome 主线继续稳定后，先完成 Edge 的独立端到端验收。复用 provider 接口，隔离浏览器注册、连接与能力协商，禁止把 Chrome 的通过结果当作 Edge 已支持。Windows/Linux 自动安装分别设门槛。

Chrome 商店资料准备可并行；开发者付费条件恢复后继续注册、提交和审核。验收商店 ID、Native Messaging 白名单、旧版迁移与错位更新兼容；商店未通过前继续诚实说明手动加载步骤。

## 五、实现约束

保留分层：DSH 入口与任务生命周期 → BrowserRuntime/动作契约 → provider → 浏览器扩展与本地连接。执行卡读取结构化任务状态，不直接控制底层 CDP；UI 的人工点选产生受校验引用，不获得额外权限。

任务状态、执行结果、控制权与页面用途分别表达。完成收尾必须幂等，清理失败可报告并恢复；不能把丢失连接等同于任务成功。跨浏览器通过能力协商降级，避免把不支持伪装为成功。

每个具体改动用对应用户场景验收，不以增加测试数量为目标。只吸收服务主线的设计：近期不扩展 cookie 搬运、多远端管理、隐身规避和通用桌面控制。

## 六、衡量竞争力

| 层级 | 指标与起始目标 |
|---|---|
| 首次可用 | 从安装到首个正确动作的时间、点击数、失败步骤；先形成基线，再定时限 |
| 日常有效 | 固定基准任务的已验证完成率，内部初始目标 ≥95% |
| 可见反馈 | 首个反馈时间、无解释等待时长、动作 P50/P95；浏览器、模型和网络耗时分别记录 |
| 控制与收尾 | Stop 后新动作、重复副作用、误关用户页为 0；正常完成后未标记临时页遗留为 0 |
| 人工协作 | 指认成功率、人工修改后继续成功率、需重启任务的次数 |
| 效率 | 同任务工具调用、token、插件 CPU/内存和观察视图资源消耗 |
| 获客 | 下载之外，观察自愿反馈中的安装成功、首任务成功和继续使用意愿 |

先建立同机、同模型、同任务、同网络条件的竞品评测，每项至少重复 3～5 次。报告版本、样本量和失败案例；未测过的维度标记未知。

## 七、对外表达

目前可用：**在已登录的 Chrome 中，让 DSH 完成网页读取和操作；提供页面内动作反馈与明确交接。** 具体支持范围及限制以 README 和发布说明为准。

下一阶段完成并验收后，增加：**临时页自动收尾、聊天内执行状态、点选目标、人工接手后继续。**

README 和市场介绍先讲用户场景，再给短录屏、三步上手和能力边界，技术架构放后面。增长应建立在首次任务成功之上，不靠“超越 Codex”或“独有虚拟鼠标”替代证明。

## 八、下一步执行清单

1. 完成 0.1.2 实际用户验收，修复安装或日常使用阻断。
2. 为阶段 B 定义任务完成语义、页面用途和清理契约，再实施最小完整流程。
3. 接入轻量执行卡，把已有错误与交接原因变成用户能处理的状态。
4. 加入对应的真实 Chrome 验收，发布收尾与可见性更新。
5. 随后推进页面指认和接手继续；按任务反馈补高频动作。
