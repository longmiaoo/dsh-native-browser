# dsh-native-browser 0.1.1

Configure Chrome from **DSH Settings → Browser setup → Set up Chrome**, without finding a Profile name or editing terminal commands.

## Install or update

1. In the DSH app you actually use, install/update `dsh-native-browser` to **0.1.1** through its plugin market. Reload DSH as instructed by the host.
2. Open **Settings → Browser setup** (中文：**设置 → 浏览器配置**), then click **Set up Chrome / 完成浏览器配置**. This configures components on the Mac running DSH and starts or updates its local login service.
3. Chrome Web Store distribution is still pending. On first installation, enable Developer mode at `chrome://extensions` and choose **Load unpacked**. Copy the extension directory from the settings page; press **⌘⇧G** in Chrome's folder picker to paste it. If already loaded from this stable directory, reload the extension after setup.
4. Allow your target tab from the extension popup, click **Check connection / 检查连接**, then ask DSH to read that page.

Desktop users should use their app's plugin market. The public CLI restricts Desktop-owned profiles; do not simply replace `web` with `desktop` in a command.

## Changes

- Fix activation in real DSH 0.2.1-rc.3 through authenticated owner-only shared routes; retain the legacy channel on older hosts.
- Add an authenticated settings-page installer, connection diagnostics, path copying and a button to reopen Chrome's extension manager.
- Resolve the currently loaded plugin's package and configured runtime directory; no Profile name is requested from the user.
- Verify Desktop's built-in Electron runtime and preserve Node mode when Chrome or the login service starts the native components. Standalone Node installations remain supported.
- Keep installation outside model-facing tools, validate fixed RPC requests, share concurrent same-directory installs and reject competing in-process directories.
- Bound platform opener/service commands, preserve existing installation checks, and correct installation/security documentation.
- Document privacy handling and prepare Chrome Web Store submission materials. No Chrome Web Store release is included in this version.

## Acceptance task

After setup and explicit tab consent, ask:

> 使用 native_browser 工具，列出 Chrome 标签页，读取刚才授权页面的标题和主要内容，然后交还控制。

Confirm that the new settings entry appears, Chrome connects, the expected tools are available, and Stop/handoff releases control. Installation does not change DSH's default action approval settings. Updating an existing Broker restarts it and can interrupt active browser work; reconnect afterwards.

## Scope

macOS + Google Chrome. The new settings integration is checked against DSH host components **0.2.1-rc.3**; older/custom clients without the settings slot API may need the CLI installation path. The existing declared host range remains unchanged. Remote DSH setup affects its host computer, not the device viewing its UI.

Screenshots and page content may be forwarded by DSH to the user's configured model provider; see [PRIVACY.md](../../PRIVACY.md). Codex is an experience target, not a measured parity claim. This release does not add a store installation button or silently install an extension into Chrome.
