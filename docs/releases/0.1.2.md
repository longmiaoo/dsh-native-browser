# dsh-native-browser 0.1.2

个人浏览模式、虚拟鼠标与会话交接修复。正式支持 macOS + Google Chrome。

## 更新内容

- 默认使用 `personal`，与标准安装器启动的 Broker 一致。普通网页无需逐页授权，插件不再追加逐动作确认；已有显式审批配置与 DSH 宿主权限继续生效。
- 每次连接与重连先校验个人模式能力，模式不匹配时提供修复指引。
- 配置页分别显示实际后台模式和插件审批模式，连接成功后隐藏已完成的安装步骤，补充 macOS 隐藏目录操作说明。
- 输入和按键时，在实际聚焦控件显示虚拟鼠标；点击、滚轮反馈继续支持。交还控制后移除，Stop 后不补发延迟注入反馈。
- 切换对话后，旧对话无法重新接管或新开浏览器标签页，工具返回明确的交接说明。切回原对话后可申请新的控制权。
- 可见但未获得焦点的 DSH 窗口不再抢占前台会话，获得焦点时重新同步。

## 安装与升级

1. 在实际使用的 DSH 应用插件市场安装或更新到 **0.1.2**，按宿主提示重载。
2. 打开 **设置 → 浏览器配置 → 完成浏览器配置**，更新本机后台与固定目录中的扩展。后台更新会中断当前浏览器操作，请在空闲时执行。
3. 已加载固定目录的用户，在 `chrome://extensions` 点击 DSH Native Browser 的“重新加载”；首次使用需开启开发者模式、加载配置页给出的整个扩展目录。在 macOS 目录选择器中可按 **⌘⇧G** 粘贴路径。
4. 点击“检查连接”，确认个人模式后即可聊天，无需逐页授权。已有显式 `per-action` / `per-lease` / `trusted` 设置优先。

Desktop 用户使用应用内插件市场与配置页，无需填写 Profile。CLI/Web 用户可使用：

```sh
dsh plugin --profile web add dsh-native-browser@0.1.2
dsh plugin --profile web exec dsh-native-browser install --browser=chrome
```

## 验收

可对 DSH 说：

> 使用 native_browser 工具，打开并激活一个普通网页，读取标题；在搜索框输入内容，让我看到操作反馈，完成后交还控制。

已通过 598 项自动化测试，以及隔离 Chrome 153.0.8010.12、Native Messaging、真实 DSH 0.2.1-rc.3 工具运行时的打包安装验收。覆盖键盘指针、交还移除、后台重新接管拒绝、切回接管与 Stop；没有模型驱动的日常账户验收。

## 已知边界

- 本版本任务完成后仍保留标签页，自动清理临时页留待后续版本。用户原有页面不会被关闭。
- 指针显示在目标 Chrome 页面，后台标签页需要激活才能看到；页面读取不会伪装成点击。
- Chrome Web Store 尚未上架，首次加载扩展仍需用户在 Chrome 确认。Edge 与完整 Linux/Windows 安装仍为实验范围。
- 历史记录未保存每次控制权释放的具体来源，不宣称所有现场 `LEASE_REVOKED` 均已复现或解决。
- 页面和截图可能由 DSH 发送给配置的模型提供商，详见 [隐私说明](../../PRIVACY.md)。Codex 为体验目标，未宣称已达到等同表现。

English summary: Default personal mode now matches the installer, keyboard input shows focused-target pointer feedback, setup reports effective modes, and foreground handoff blocks background reclaims. Explicit approval settings and host permissions still apply. Reload both DSH and the staged Chrome extension after setup. Automatic temporary-tab cleanup and Chrome Web Store distribution are not included.
