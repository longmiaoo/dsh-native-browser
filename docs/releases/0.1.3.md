# dsh-native-browser 0.1.3

任务临时页收尾、页面保留标记与执行状态。正式支持 macOS + Chrome。

## 更新

- 新增第 14 个工具 `native_browser_task`：查询任务状态、标记页面用途、明确完成并清理。
- 个人模式下，宿主明确返回正常 completed 轮次结束时，自动清理仍受控且未保留的临时页；交付页、待接手页、用户原有页保留。跨轮次任务需要提前标记 handoff。
- 切换、中断、未知结束原因不触发自动关页。过期或已撤销控制权的页面跳过并报告，清理不会重新抢控制或盲目重试。
- 聊天中的可选操作卡显示执行状态、耗时、未验证提示和收尾数量。截图沿用宿主图片展示。
- 设置 → 浏览器配置显示当前对话任务状态，提供 Stop 与“完成并清理临时页”。
- 清理在等待连接前占用任务，并保持到释放控制响应返回，防止并发操作插入收尾。

## 升级与试用

1. 在你实际使用的 DSH 应用中，把插件更新到 **0.1.3**，按宿主提示重载。
2. 进入 **设置 → 浏览器配置 → 完成浏览器配置**，更新本机组件；在 Chrome 扩展管理页重新加载 DSH Native Browser，再检查连接。后台更新会中断当前操作，请在空闲时执行。
3. 若市场卡片仍显示旧版本，它可能是目录快照；核对已安装插件详情是否为 0.1.3。

Desktop 用户使用应用内插件管理与配置入口。CLI/Web 用户可使用对应 profile 的命令：

```sh
dsh plugin --profile web add dsh-native-browser@0.1.3
dsh plugin --profile web exec dsh-native-browser install --browser=chrome
```

建议验收提示词：

> 使用 native_browser 工具打开并激活两个普通资料页，读取内容。把我需要继续查看的结果页标记为 deliverable，其他页面保持 temporary。最后用 native_browser_task finish 收尾，告诉我关闭、保留和跳过的数量。

再测试切换对话、Stop 与等待登录，确认不会误关原有页面或重新抢控制。正常结束的兜底关页不等于自动识别所有业务目标；未完成页面应先标记 handoff。

## 验证与边界

- 607 项自动化测试通过；真实隔离 Chrome 153.0.8010.12 + Native Messaging + DSH 0.2.1-rc.3 工具运行时的打包安装验收通过。
- 覆盖临时页关闭、交付/待接手/用户页保留、重复收尾、completed 宿主事件自动清理、失效控制和并发隔离。
- 真实 SlotCore/React 验证任务设置面板与聊天工具卡；尚无完整 Desktop 外壳及模型自主长期任务验收。
- 登记保存在当前插件进程内；重启不恢复历史页面的清理权。旧宿主结束格式未知时需使用显式 finish。现有控制已失效时可能留下待处理页。
- 本版仍需首次手动加载扩展，Chrome Web Store 尚未上架。Edge 和完整 Linux/Windows 安装仍属实验范围。

English: Adds task page-purpose marks, explicit finish, completed-turn cleanup in personal mode, and optional action/status UI. Only still-controlled temporary task-created tabs are closed. User, deliverable and handoff tabs remain open. Revoked authority is never reclaimed for cleanup. In-memory tracking does not survive restart; full Desktop and model-driven acceptance remain pending.
