# dsh-native-browser 0.1.5

修复当前 DSH 中“当前对话被误判为后台、连列出浏览器都被拒绝”的问题。

## 原因与修复

旧插件读取 `sessions.list.current`，但当前 DSH Session Controller 使用 catalog 的 `byId` 与本地 `retainedBy.mainView` 表示主视图对话。缺失字段被误上报为没有前台对话，后端因而拦截请求；模型可能再误解释成旧租约被占用。

本版改为：

- 使用唯一的 `mainView` 会话，同步修正设置页任务状态；不从缓存或侧栏中猜测当前会话。
- 兼容旧宿主明确提供的 `current` 字段；待加载、未知或有歧义的快照不会被猜为另一个会话。
- 前台通知失败时，不再缓存为成功同步，后续同一选择的更新可以再次同步。
- 区分“前台未同步”和“浏览器租约占用”：提示明确说明请求尚未联系 Chrome，避免要求用户关闭无关页面或释放不存在的租约。
- 真正切换到后台的对话仍被拦截，Stop、交还控制与页面收尾规则继续生效。

## 更新与验收

在实际使用的 DSH 应用中更新到 **0.1.5**，然后重载 DSH；如仍加载旧客户端，完全退出后重新打开。已经配置好 Chrome 的用户，无需为此修复关闭浏览器标签页、调整完全权限或重新加载扩展。

CLI/Web 用户可在自己的 profile 中使用固定版本，例如：

```sh
dsh plugin --profile web add dsh-native-browser@0.1.5
```

在 GUI 中选中当前对话，然后说：

> 先使用 native_browser_list 列出已连接的浏览器，再列出 Chrome 标签页。不要关闭或更改任何页面。

确认列表可用后，再测试普通网页读取、切换对话和返回。若仍有问题，保留原始工具错误用于诊断，不能仅凭模型的自然语言总结判断是租约冲突。

## 验证范围

- 612 项自动化测试、类型检查与打包安装检查通过。
- 新增客户端 catalog、mainView 唯一性、缓存/侧栏排除、旧接口兼容、通知失败恢复测试。
- 加载实际 client.js，经认证前台桥接到真实 Broker，验证同一可见会话能恢复浏览器列表；该契约测试使用 FakeProvider，无浏览器动作。
- 隔离 Chrome 中真实 SlotCore/React 组件使用 mainView catalog 验证状态面板，覆盖没有会话及异常响应。
- 以上不是完整 Desktop 外壳与模型自主日常任务的验收声明。Chrome Web Store 尚未上架，正式支持范围仍为 macOS + Chrome。

English: Fixes foreground detection on modern DSH catalogs using unique mainView retention instead of the removed list.current field. Task settings use the same selection source. Legacy explicit selection remains supported, and missing foreground synchronization is no longer described as a busy browser lease. Update and reload DSH; no Chrome tab closure or permission changes are needed.
