# dsh-native-browser 0.1.7

安装后直接找到 Chrome 配置向导：新增插件详情配置、侧栏“浏览器”入口和启用后的连接引导，并把完整安装步骤放到中英文 README 顶部。

## 本版改动

- 在 DSH 原生插件详情页直接显示配置向导，组件提供“配置”入口，详情页头增加“配置浏览器”按钮。只对本插件显示，不影响其他插件。
- 侧栏新增“浏览器”面板，提供“返回对话”；不再只依赖设置中的入口。未提供新插槽的旧宿主保留设置页。
- 接入宿主的启用后引导卡片，点击“现在连接 Chrome”进入详情。引导由宿主在显式启用后触发，不承诺所有第三方市场界面都会显示此卡片。
- 用三步进度说明“插件已安装 → 配置本机 Chrome → 加载扩展并检查连接”，提供可复制的第一次对话指令。连接成功后收起目录等高级内容。
- 回到 DSH 窗口时自动重新检查连接。打开向导、切换面板、展示引导卡片只读取状态；只有点击“完成浏览器配置”才执行本机配置并打开 Chrome。
- README 顶部明确安装、配置、Mac 目录选择快捷键、第一次使用，以及 DSH 顶部“已安装”和市场内部同名列表的区别。包介绍也提示安装后的配置入口。

## 升级和使用

1. 在当前 DSH 应用的插件市场更新到 **0.1.7**，按宿主提示重载；若仍是旧界面，完全退出 DSH 后重开。
2. 点左侧 **浏览器**，或 **插件 → 顶部“已安装”→ dsh-native-browser 卡片名称**，进入配置向导。这里的“已安装”是 DSH 顶部标签，不是插件市场内部的同名列表。
3. 新用户点击 **完成浏览器配置**，程序会打开 Chrome 扩展管理页和扩展文件夹。首次在 Chrome 开启开发者模式并加载该目录；Mac 目录选择器可按 **Command + Shift + G** 粘贴向导中的完整目录。
4. 返回向导检查连接，看到 **Chrome 已连接** 后复制试用指令到 DSH 聊天即可。

旧宿主缺少新入口时，继续使用 **左下角更多 → 设置 → 设置左侧浏览器配置**。已连接的 Chrome 无需为了使用新向导删除再安装；如果重新运行配置同步了扩展，在 Chrome 扩展卡片上点“重新加载”。

CLI/Web 用户可在已知的实际 profile 中更新，例如：

```sh
dsh plugin --profile web add dsh-native-browser@0.1.7
```

Desktop 用户优先从应用内更新，无需寻找 Profile。公开 README 不知道每个人的本地 DSH 地址和认证状态，因此不提供猜测的 localhost 跳转链接；应用内向导使用当前已认证的 DSH 连接。

## 验证和范围

- 617 项自动化测试、类型检查、元数据及依赖边界检查。
- 真实 DSH SlotCore、共享 React 与隔离 Chrome 渲染实际 client.js：覆盖启用引导到详情、详情到主面板、返回对话、组件配置、旧宿主设置回退、复制指令、回到窗口自动检查、无当前对话及异常任务状态。
- 验证只打开页面不会安装或打开 Chrome，其他插件不显示本插件按钮；安装测试使用临时目录和隔离组件，不修改用户的服务或日常 Profile。
- 打包安装、重复安装、旧版迁移及 Chrome MV3 检查。本版不增加浏览器权限或更改默认审批模式，正式支持仍为 **macOS + Chrome**，Chrome Web Store 尚未上架。
- 组件集成测试不等同于完整 Desktop 外壳与第三方市场安装过程的端到端验收。
