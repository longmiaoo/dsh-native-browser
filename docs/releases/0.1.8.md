# dsh-native-browser 0.1.8

修复安装后侧栏“浏览器”短暂出现、重载后消失的问题。安装或更新后，按宿主提示重载 DSH，即可从侧栏打开配置向导。

## 修复

真实宿主在 Layout 服务完成激活前声明主面板插槽。0.1.7 此时查询服务并提前返回，导致面板和侧栏入口遗漏；安装后的热加载可能正常，冷启动或界面重新初始化却会丢失。

本版直接随插槽声明注册面板和导航，在用户点击导航时才读取 Layout 服务；宿主重建布局时也会重新注册。保留插件详情和设置页中的配置入口。

## 升级

- Desktop 用户在当前 DSH 的插件管理中更新到 **0.1.8**，按提示重载；如仍显示旧界面，完全退出 DSH 后重开。
- 点击左侧 **浏览器**，或 **插件 → 顶部已安装 → dsh-native-browser** 进入配置向导。
- 此修复只改 DSH 前端入口，不需要删除 Chrome 扩展或重做已完成的浏览器配置。缺少侧栏插槽的旧宿主仍使用 **更多 → 设置 → 浏览器配置**。

CLI/Web 用户可在实际使用的 Profile 更新，例如：

```sh
dsh plugin --profile web add dsh-native-browser@0.1.8
```

## 验证

- 真实 Cordis 与 SlotRegistry 回归覆盖冷启动、热加载、Layout 销毁及重建、插件卸载；固定测试 SDK 版本并纳入自动测试。
- 本机 DSH Desktop 实际重载后侧栏入口出现，点击打开配置向导。
- 独立发布目录通过 618 项自动化测试，以及类型、元数据、依赖边界、向导组件集成和打包安装检查。
- 正式支持范围仍为 macOS + Chrome；本版不增加浏览器权限，不改变审批模式。真实生命周期测试不等同于全部宿主版本的 Desktop 端到端覆盖。

English: Fixes the Browser sidebar disappearing on cold boot or Layout reactivation. Update to 0.1.8 and reload DSH. Existing Chrome setup does not need to be repeated for this UI fix. Adds a regression against the actual Cordis and SlotRegistry lifecycle.
