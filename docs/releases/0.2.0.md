# dsh-native-browser 0.2.0

安全加固版本：上传、选择文件和下载每次都会请你确认，上传只限于允许的目录；扩展只运行固定的页面函数；模型不能再把页面导向本机或内网地址。同时修复长时间运行后的连接和重放保护问题，并整理内部结构。

## 行为变化（请注意）

- **文件操作每次确认。** 上传、选择文件、下载在所有审批模式下（包括默认的个人模式）都会弹出确认，并列出具体的本地路径。没有 DSH 审批服务时会被拒绝。`batch` 不再接受这几类动作。
- **上传目录受限。** 默认只允许 `~/Downloads`、`~/Desktop`、`~/Documents` 中已存在、非隐藏的普通文件；符号链接先解析再判断，Broker 自己的运行目录始终被排除。需要其他目录时，在 `broker` 或 `install` 命令上加 `--upload-root=/绝对路径`。
- **旧的动作日志会被清除一次。** 日志现在用从本地 token 派生的密钥（HKDF-SHA256）认证，旧的 `action-journal.jsonl` 无法验证，首次启动时删除，新文件是 `action-journal.v2.jsonl`。最长 24 小时的重放保护会失效一次。

## 安全

- 标签页清单不再包含查询参数和片段；模型不能打开或从公网页面导航到本机、内网地址。
- 页面状态检查在隔离世界里运行，页面无法伪造结果；扩展在根会话只执行固定、已审查的页面函数。
- 只报告归属于当前控制权的下载。
- Broker 启动失败期间，不再接受此时连入的连接。

## 修复

- 长期运行的 Broker 或扩展连接不再在第 10,000 个请求时断开；重放保护改为只保留最近一段请求 ID。
- 长期运行的 Broker 不再在 10,000 次动作后让每个动作都返回 `JOURNAL_FULL`；已释放控制权的身份栅栏会被回收，持久日志继续提供跨控制权的重放保护。
- 修复富文本（`contenteditable`）编辑框的填写和追加被扩展以 `POLICY_DENIED` 误拒：页面函数嵌入的 `editableText.toString()` 在 Broker 与扩展两份构建中格式不同，导致精确匹配的白名单不通过。现在两边使用同一份固定源码。

## 改进

- 配置页标题旁显示插件版本。
- 工具参数定义更短，规则不变：`act` 和 `batch` 共用同一份动作和期望定义，部分工具描述压缩（定义文本总量约从 39k 降到 24k 字符）。接受和拒绝的输入都与以前一致。
- 内部模块拆分，行为不变：CDP 命令守卫、指针与活动反馈、上传/选择文件/下载/对话框/视觉点击分别移到独立文件；Broker 与扩展共用请求追踪；适配层的审批规则集中到一个文件。
- 文档更正：MV3 service worker 不在 `chrome.storage` 保存状态，重启后会丢失控制权并以关闭方式失败。

## 升级步骤

1. 在当前 DSH 的插件管理中更新到 **0.2.0**，按提示重载 DSH。
2. 打开左侧 **浏览器**，点击 **完成浏览器配置**，同步新版 Broker 和扩展文件。
3. 到 Chrome 扩展管理页，在 DSH Native Browser 卡片点击 **重新加载**。
4. 回到配置页检查连接，再开始聊天。

本版需要新版后台和 Chrome 扩展，仅重载 DSH 不会生效。

CLI/Web 高级用户可更新自己实际使用的 Profile，例如：

```sh
dsh plugin --profile web add dsh-native-browser@0.2.0
dsh plugin --profile web exec dsh-native-browser install --browser=chrome
```

支持范围仍为 **macOS + Chrome**。Chrome 商店版仍未上架，首次安装仍需确认加载已解压的扩展。

English: Security hardening release. File upload, file chooser and download ask for approval on every call in every mode and uploads are confined to allowed folders; the extension runs only a fixed set of page functions; the model can no longer steer a public page to local or private addresses. Fixes long-running connection and replay-protection limits and a rich-text fill denial. Upgrade deletes the old action journal once.
