# 任务收尾与执行状态（0.1.3）

0.1.3 新增第 14 个工具 `native_browser_task`，并提供任务收尾与执行状态。升级后需重载 DSH。

## 前台同步修复（0.1.5）

0.1.4 及之前版本错误读取 `sessions.list.current`。核对 DSH 0.2.1-rc.3 的 Session Controller 源码，其 catalog 只有 ids/byId/phase 等字段；宿主布局使用 byId 中唯一的 `retainedBy.mainView > 0` 行确定当前对话。旧插件读到 undefined 后上报 null，后端把正在显示的对话挡在浏览器请求之前，模型又将其误解释为租约占用。

修复统一前台桥接与设置面板的选择来源：优先使用宿主 mainView 保留标记，兼容旧宿主显式 current；不从 sidebar/cache 行猜测，不将未知或待加载数据当作已明确取消选择。前台通知失败后不会缓存成功状态。后端的“未同步当前对话”说明明确指出尚未联系 Chrome，不应让用户关闭标签页或释放并不存在的旧租约。

该修复补充真实 catalog 结构下的前端测试，以及加载实际 client.js、经过后端前台桥接、解锁当前会话浏览器列表的契约测试。隔离 SlotCore/React 验收改用 mainView catalog；仍不等于完整 Desktop 外壳验收。本机安装已应用同等客户端临时补丁，需重载 DSH 生效；0.1.5 正式包包含相同的客户端修复和更准确的后端诊断提示。

## 使用契约

助手通过 `native_browser_open` 新建的页面默认是 `temporary`。用户原有页面不进入清理登记，始终保留。

```json
{"action":"mark","leaseId":"<当前任务页租约>","purpose":"deliverable"}
```

用途可选 `temporary`（搜索、中间资料）、`deliverable`（用户需要继续使用的结果页）、`handoff`（待登录、确认或尚未结束的工作页）。标记仅作用于当前对话创建并仍受控的页面，不能标记别的对话或用户页面。显式 `native_browser_handoff` 也会将对应任务页保留为待接手页。

`native_browser_task({action:"finish"})` 完成当前浏览器工作：关闭仍有有效控制权的临时页，保留交付与待接手页，然后释放控制。返回 `closed`、`retained`、`skipped` 和状态；`skipped` 非零时不能报告全部清理成功。重复调用不会重放失败的关页动作。

个人模式还监听宿主的 `turn/end`，只有明确的 `data.reason.kind=completed` 才自动收尾。这是正常轮次完成的兜底，并非通用业务目标识别：跨轮次未完成页面应在本轮结束前标记 `handoff`。未知结束格式不触发关页；中断、错误、切换对话也不触发关页。显式逐动作审批模式保留自己的审批，完成时使用经过审批的 `task finish`。

当前标记是保守保留：它们在本次插件生命周期内持续有效，不会因下一轮自动变回临时页。希望关闭时可重新接管并明确标记 temporary，或调用已有 close。普通 release_all 只交还控制并保留全部页面，不能代替 finish。

## 控制边界

- 清理在等待连接前同步占用任务，直到释放控制得到响应后才允许新动作进入；进行中的操作会阻止开始清理。
- 仅使用已有租约关页。Stop、过期、断线、对话切换后不会为了清理重新接管。
- 连接或租约失效导致跳过时页面保留并报告待处理。关页响应不明不自动重试，避免重复副作用。
- 切换对话的同步撤销会中断收尾信号，底层租约与扩展 gate 继续检查权限。
- 登记仅在内存中，最多 128 个会话状态、每个会话 64 个任务页。插件、浏览器或后台重启后不凭历史数字 ID 清理旧页；这版没有恢复跨重启任务清理能力。
- 完成收尾释放交付/待接手页的控制，但保留标签页，不清理用户浏览记录或登录信息。

## 用户界面

支持 `tool.call.toolview` 的宿主在聊天中显示浏览器操作卡：准备/执行、运行耗时、未验证结果提示和收尾数量，详情仍可检查。截图工具沿用宿主图片展示。旧宿主没有该插槽时继续使用通用工具展示。

设置 → 浏览器配置中显示当前对话的任务状态，并提供 Stop 和“完成并清理临时页”。可见时轮询，离开组件会取消请求。当前只显示执行元数据：动作、时间、状态、页面用途和诊断代码；不额外采集页面正文、URL、输入文本、密码或令牌。不把“调用返回”当作业务已成功。

新增 `task.status`、`task.stop`、`task.finish` 端点沿用认证 owner 路由，固定参数为 `{sessionId}`，变更操作检查当前对话。状态读取不启动 Broker、不执行页面动作。手动清理只针对该对话登记的页面；后台对话不能使用该入口抢回控制。

## 验证

- 单元/适配器：用途保留、用户页保护、跨 owner 拒绝、重复收尾、未知/中断结束、失效租约、并发收尾、取消、释放响应前的操作隔离。
- 已运行真实 Chrome 153.0.8010.12 + Native Messaging + DSH 0.2.1-rc.3 工具运行时的打包安装验收：临时页关闭、交付/待接手/用户页保留、重复收尾、模拟 completed 宿主事件自动关页。
- 真实 SlotCore/React 组件验收：设置中的当前任务、手动清理状态和聊天工具收尾卡，截图 `output/playwright/task-card.png`。
- 验收使用隔离 Chrome 和临时 Broker，不操作用户日常浏览器；没有模型自主标记交付页的真实业务验收，也没有完整 Desktop 外壳验证。

后续需要验证多轮模型是否稳定遵守用途标记、不同宿主结束原因格式、完整 Desktop 卡片和长任务收尾策略。上述项目未通过前不宣传“自动理解所有任务是否完成”。
